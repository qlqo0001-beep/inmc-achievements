# inmc-achievements

단계·체인·히든·연출을 갖춘 업적 플러그인. **모든 설정을 게임 안 화면에서** 합니다.

```
/업적              내 업적 목록
/업적 길라잡이      처음 온 사람을 위한 순서
/업적 통계 [대상]   달성률·점수·랭크
/업적 우편함        인벤이 가득 차서 못 받은 보상
/업적 관리          관리자 화면 (권한: inachievements.admin)
```

---

## 조건 네 갈래

| 갈래 | 무엇 | 특징 |
|---|---|---|
| **바닐라 통계** | 블록 파괴 · 걸음 수 · 몹 사냥 · 제작 · 낚시 … | **소급 적용됩니다.** 업적을 오늘 만들어도 어제까지 한 것이 이미 세어져 있습니다. 리스너 0개 |
| **InMC 사건** | 낚시로 물고기를 잡음 · 상자를 엶 · 몬스터를 잡음 … | 그 플러그인이 켜져 있으면 편집 화면에 **진짜 목록**이 나옵니다 |
| **상태** | 권한 그룹(LuckPerms 등급) · 지역 방문 · 선행 업적 · 아이템 소지 · 랭킹 등수 | 참/거짓이라 **단계를 가질 수 없습니다** |
| **커스텀** | 외부 플러그인이 API 로 등록한 조건 | 없는 동안에는 "모름" 으로 남습니다 — 0으로 치지 않습니다 |

> ⚠ **통계 기반 업적은 접속 중에만 진행합니다.** 마인크래프트가 오프라인 플레이어의
> 통계를 서버에 내주지 않습니다. 통계 화면에 "마지막 확인" 시각이 같이 나옵니다.

## 단계

`나무 100개 → 나무꾼 I`, `1,000개 → II`, `10,000개 → III` 처럼 **업적 하나가 단계를 갖습니다.**
업적 셋으로 나누지 않는 이유는 진행도가 하나여야 하기 때문입니다.

여러 단계를 한 번에 넘으면 **보상은 전부 받고 연출은 최고 단계만** 뜹니다.

## 히든

발견하기 전에는 이름·설명·조건이 전부 `???` 로 감춰집니다. 발견 조건은 일곱 가지:

```
자동(조건 달성 시) · 다른 업적 달성 · 특정 사건 · 지역 방문
아이템 사용 · NPC 대화 · 커스텀
```

**발견 전에도 진행도는 쌓입니다.** 그래서 나중에 발견하면 이미 한 만큼이 그대로 반영되고,
`발견 즉시 달성` 을 켜면 발견하는 순간 완료됩니다.

`전체 개수에 포함` 을 끄면 "달성률" 분모에서 빠집니다. **점수는 그대로 줍니다** — 그래서
달성률 100% 와 최대 점수가 다를 수 있고, 화면에도 그렇게 적혀 있습니다.

## 연출

업적마다, 그리고 단계마다 따로 정할 수 있습니다.

| 칸 | |
|---|---|
| 범위 | 본인만 · 주변(반경) · 같은 월드 · 서버 전체 |
| 토스트 | 마인크래프트 고유의 달성 알림창 |
| 화면 제목·부제목 · 소리 · 폭죽 · 입자 · 채팅 공지 | |

**서버 최초 달성**에게만 따로 줄 보상과 연출을 둘 수 있습니다.

오프라인일 때는 범위마다 다르게 다룹니다 — `본인만` 은 다음 접속에 한 번, `서버 전체` 는
즉시, `주변`·`월드` 는 **기준 위치가 없어 하지 않습니다.**

## 지역

WorldGuard 없이 `/업적 관리 → 지역 관리` 에서 두 지점을 찍어 만듭니다.

기본은 **5초 주기 표본 검사**라 리스너가 늘지 않지만, 5초 안에 지나가면 안 잡힙니다.
비밀 장소처럼 "밟으면 반드시" 인 곳만 **정밀 검사**를 켜세요 — 그 지역만 이동마다 봅니다.

## 랭크

업적 점수 합계로 오릅니다. `config.yml` 의 `ranks` 에서 고칩니다.

점수는 **저장하지 않고 기록에서 계산합니다.** 관리자가 단계를 지우면 그만큼 줄어드는 것이
정상이고, 그때 오프라인 플레이어까지 순위표가 다시 세워집니다.

## 소급 — 이미 한 사람들

통계 업적을 새로 만들거나 단계를 끼우면 **이미 그만큼 한 사람들이 한꺼번에 달성합니다.**
업적 설정 화면의 **"이미 해 둔 것으로 달성"** 칸(시계 아이콘)으로 정합니다.

| | |
|---|---|
| 조용히 (기본) | 보상은 주고, 공지·폭죽·토스트와 서버 최초 경쟁은 하지 않습니다 |
| 연출함 | 평소처럼 연출합니다 |

## 정의 파일을 손으로 고칠 때

읽지 못한 정의(오타·중복 단계 등)는 콘솔에 이유를 남기고 **그대로 보존합니다** — GUI 에서
다른 업적을 고쳐 저장해도 지워지지 않습니다. 고친 뒤 `/업적 관리 리로드` 하세요.

---

## 다른 플러그인에서 쓰기

```kotlin
// 1) 준비되면 평가기를 등록한다. 양쪽 다 필요하다 — 어느 쪽이 먼저 켜질지 모른다.
if (AchievementsApi.isReady()) register()

@EventHandler fun onReady(event: AchievementsReadyEvent) = register()

fun register() {
    AchievementsApi.registerCondition(this, "dungeon_clear") { playerId, value ->
        myDungeonStats.clears(playerId, value)
    }
}

override fun onDisable() {
    AchievementsApi.unregisterAll(this)   // 람다가 클래스로더를 붙들고 있다
}

// 2) 진행도를 직접 밀어줄 수도 있다. **커스텀 조건에만 통한다.**
AchievementsApi.progress(playerId, achievementUid, 1)

// 3) 업적을 몰라도 신호만 쏘면 된다.
AchievementsApi.signal("mydungeon", "clear", playerId, subject = "dungeon_1")
```

`progress` 가 `Custom` 조건에만 통하는 것은 의도입니다 — 통계 업적을 밀어 올려도 5초 뒤
스윕이 바닐라 값으로 덮어써서 **조용히 아무 일도 안 일어납니다.** 조건마다 진행의 원천은
하나여야 합니다.

**열쇠는 `id` 가 아니라 `uid` 입니다.** 업적 이름은 바뀌지만 uid 는 안 바뀝니다.
`/업적 관리` 의 아이템 설명에 같이 나옵니다.

---

## 알아둘 것

- **`achievements.yml` 의 `uid` 는 손대지 마세요.** 플레이어 기록이 그 값을 가리킵니다.
  `id`(항목 이름)는 얼마든지 바꿔도 됩니다.
- **업적의 토스트 아이콘·제목을 고치면 서버를 다시 켜야 반영됩니다.** 마인크래프트가
  발전과제 정의를 실행 중에 교체할 방법을 주지 않습니다. 다른 설정은 `/업적 관리 리로드` 로
  즉시 먹습니다.
- **`/업적 관리 미지급`** 에는 "지급했는지 결과를 모르는" 것만 나옵니다. 서버가 보상을
  주는 도중에 죽었을 때뿐이라 평소에는 비어 있고, **자동으로 다시 주지 않습니다** —
  재지급은 돈 복제 위험이 있어 관리자가 정합니다.
- 통계 업적을 새로 만들면 이미 조건을 채운 사람들이 **한꺼번에** 달성합니다. 보상은 주되
  연출은 생략하고, 틱당 처리 수를 제한해 서버가 멈추지 않게 합니다.

## 배포 전

- ⚠ `MetricsHook.PLUGIN_ID` 가 **0** 입니다. bStats 에 등록하고 바꾸세요.
- ⚠ **실기동 검증이 없습니다.** 순수 로직은 테스트로 덮었지만 Bukkit 배선은 서버에서
  한 번 확인해야 합니다.
